# PRep — project guide

A Chrome (MV3) extension that quizzes you on pull-request changes. Click a changed
code block on any GitHub PR; a card asks one multiple-choice question about what the
code does and shows a plain-language explanation after every answer. Questions are
generated by a **Portkey** AI gateway (Claude Sonnet 4.6 on Bedrock).

## Stack

- **TypeScript**, bundled by **Vite + @crxjs/vite-plugin** into `dist/`.
- **bun** as the package manager and task runner.
- **zod** is the single source of truth for the quiz shape (type + validator + tool JSON schema).

## Commands

```bash
bun install          # install deps
bun run dev          # Vite dev build with HMR (load dist/ unpacked once)
bun run build        # typecheck + production build into dist/
bun run typecheck    # tsc --noEmit
bun run lint         # eslint
bun run format       # prettier --write
```

Load the extension: `chrome://extensions` → Developer mode → **Load unpacked** → select `dist/`.

## Architecture

The build emits one bundle per entry point — there is no shared global namespace; modules `import` each other.

- `src/manifest.config.ts` — typed MV3 manifest (CRXJS resolves the TS entry points + rewrites icon paths).
- `src/background/` — the service worker, the **only** holder of the API key and the **only** origin that calls Portkey.
  - `index.ts` routes messages · `portkey.ts` is the HTTP client · `quiz.ts` builds the prompt + validates output.
- `src/content/` — runs in the page (never sees the key).
  - `index.ts` orchestrates (click → box → card → grade) · `selectors.ts` is the **only** place GitHub DOM coupling lives · `card.ts` is the Shadow-DOM UI.
- `src/popup/` — toolbar settings (Portkey URL, API key, model).
- `src/shared/` — `messages.ts` (typed message contracts), `settings.ts` (storage), `quiz.ts` (zod schema/type/validator).

## Conventions

- **Commits: Conventional Commits, short and simple** — `feat:`, `fix:`, `chore:`, `docs:`, etc.
- All GitHub DOM selectors live in `src/content/selectors.ts` — if GitHub changes its diff markup, fix it there and nowhere else.
- The key never leaves the service worker / `chrome.storage.local`. Content scripts only send extracted code text.

## CI / Release

- **CI** (`.github/workflows/ci.yml`) runs lint + typecheck + build on every push to `main` and every PR.
- **Release** (`.github/workflows/release.yml`) runs **semantic-release** on every push to `main`. It reads the Conventional Commits since the last release, picks the next version, tags it, builds + zips `dist/`, publishes a GitHub release with the zip attached, and commits the `package.json` version bump back to `main`. **No manual tagging.**

Releases are fully driven by commit messages, so the convention is load-bearing:

| Commit prefix | Effect |
|---|---|
| `fix:` | patch release (0.0.x) |
| `feat:` | minor release (0.x.0) |
| `feat!:` / `BREAKING CHANGE:` in body | major release (x.0.0) |
| `chore:`, `docs:`, `ci:`, `refactor:`, etc. | no release |

The manifest version comes from `package.json` (`src/manifest.config.ts` imports it), and semantic-release bumps `package.json` before the build — so the released zip always carries the right version.
