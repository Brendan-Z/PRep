# PRep

A minimal Chrome extension that quizzes you on pull-request changes so you actually understand
the code before approving it.

On any GitHub / GitHub Enterprise **Files changed** page, click a changed block of code. The
extension draws a box around it and asks **one multiple-choice question (4 options)** about what
that code does. After you answer — right or wrong — it reveals a **junior-friendly, plain-language
breakdown** of exactly what the code does and why the correct option is right.

Questions are generated by your **Portkey** AI gateway (configured to **Claude Sonnet 4.6 on AWS
Bedrock**), called directly from the extension. No backend, no accounts — everything is local.

## Install (load unpacked)

1. Open `chrome://extensions`.
2. Toggle **Developer mode** (top-right).
3. Click **Load unpacked** and select this `PRep` folder.
4. Confirm the service worker registers (no errors under the extension card).

## Set up

Click the **PRep** toolbar icon to open the popup:

- **Portkey URL** — defaults to `https://api.portkey.ai/v1`; change only for a self-hosted gateway.
- **API key** — your Portkey API key. Stored only in `chrome.storage.local` on this device.
- **Model** — the exact Bedrock model id for Claude Sonnet 4.6, e.g.
  `us.anthropic.claude-sonnet-4-6-...`. **Set this to your account's real id.**
- Click **Save**, then **Test connection** to confirm Portkey responds.

The extension works on `github.com` and any GitHub Enterprise host out of the box — no per-host
configuration. (This requires broad site access at install time; see the security note.)

## Use

Open a PR's **Files changed** tab and click a changed line. A card appears with a question and four
options. Pick one — the card highlights the correct answer and shows a plain-language explanation
after every answer.

## Security note

To work on any GitHub host without configuration, the extension requests access to all `https://`
sites — Chrome shows *"read and change all your data on all websites"* at install. The content
script does nothing until you click a changed line on a PR/commit/compare page.

A Chrome extension runs in the browser, so any key it holds is recoverable by local malware or disk
access, and `chrome.storage` is not encrypted. Mitigate by using a **scoped Portkey key with a
budget and rate limits**, and rotate it. The key lives only in the background service worker and
`chrome.storage.local` — it is never exposed to page or content-script context, and it never syncs
across devices.

## Maintenance

- **When GitHub changes its diff DOM**, the fix is in one file: `selectors.js`. It supports both the
  classic table view (common on GitHub Enterprise Server) and the newer React view, detected at
  runtime. React CSS-module classes are matched by prefix (hashes change between deploys).
- **Structured output**: the worker forces an `emit_quiz` tool call (Claude's native, reliable JSON
  path through Portkey's OpenAI-compatible API). If a gateway/model doesn't honor tool calling, it
  falls back to prompting for raw JSON and validating it. Both paths require exactly 4 options and a
  valid `correctIndex`.

## Files

| File | Purpose |
|---|---|
| `manifest.json` | MV3 manifest, permissions, content-script matches |
| `background.js` | Service worker — the only key-holder; Portkey call |
| `selectors.js` | All GitHub DOM coupling: view detection + dual selector map |
| `content.js` | Orchestrator: click → box → card → quiz → grade |
| `card.js` | Shadow-DOM quiz card + overlay box |
| `popup.html` / `popup.js` | Toolbar popup settings (Portkey URL, API key, model) |
